# JSON Lens Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the isolated parser task and direct integration for the browser extension. Steps use checkbox syntax for tracking. The user already approved implementation; continue through verification without additional design gates.

**Goal:** Deliver a directly loadable Chrome JSON viewer with lossless formatting and explicit AI extraction.

**Architecture:** ES modules packaged locally with no runtime dependencies. A lossless parser retains token spans; a worker serves parsing and extraction. Extension pages provide editing and settings; a service worker handles context menus and transient payloads; a content script enhances JSON response documents.

**Tech Stack:** Manifest V3, JavaScript modules, CSS, Node built-in test runner, Chromium browser verification.

---

## Files and tasks

- [x] **1. Lossless JSON core** — `extension/core/json.js`, `extension/core/extract.js`, `tests/json.test.mjs`, `tests/extract.test.mjs`. Test exact integer/exponent/string/member preservation, duplicate members, errors with line/column, nested delimiters in strings, multiple top-level candidates and escaped JSON. Export `parseJSON(source)`, `formatJSON(source, indent = 2)`, `minifyJSON(source)` and `extractCandidates(text)`. Nodes contain `{type,start,end,children?,key?,keyRaw?}`; object child nodes represent values with member keys. Parsing rejects trailing input. Formatting changes only whitespace. Extraction returns complete outermost objects/arrays as original raw strings and their source positions.
- [x] **2. LLM protocol** — `extension/core/llm.js`, `tests/llm.test.mjs`. Normalize a configured Base URL to `/chat/completions`, validate settings, enforce the AI byte limit, classify provider errors, and support AbortSignal plus timeouts. Have the model identify exact raw JSON strings. Independently validate every returned result against the source or a decoded JSON-string source; reject fabricated/changed values and incomplete model output. Keep credentials out of error messages.
- [x] **3. Extension integration** — `extension/manifest.json`, `extension/background.js`, `extension/content.js`, `extension/worker.js`. Register the two selection menus and toolbar entry, use one-time transient handoff, restrict sensitive storage, and enhance only JSON documents in place without a second network fetch. Read the original source before changing the document. Expose only the viewer page needed for embedding; validate all incoming message types and senders.
- [x] **4. Viewer and settings** — `extension/viewer.html`, `extension/viewer.js`, `extension/tree.js`, `extension/style.css`, `extension/options.html`, `extension/options.js`. Build a Chinese two-pane editor, bounded tree rendering, search, selected-node path, result picker, source restoration, clipboard/download actions, live validation, cancellable AI state and local settings. Use textContent for untrusted content. Keep the last valid tree visibly stale while editing invalid JSON. Disable export for invalid input.
- [x] **5. Build, documentation and checks** — `scripts/build.mjs`, `README.md`, `tests/browser.mjs`. Build by copying extension assets and validating the manifest. Run `npm test`, `npm run build`, then load the extension in an isolated Chromium profile. Serve local JSON and a mock OpenAI-compatible endpoint to verify actual extension APIs, JSON MIME enhancement, precise numeric text, editing, search, AI success/error/cancel and no mutation of ordinary HTML.

## Verification commands

```sh
rtk npm test
rtk npm run build
rtk npm run test:browser
```

Pass criteria: all unit tests pass; build reports a complete extension; browser assertions pass without uncaught errors. Report any actual provider or browser limitations honestly. Review requirements first, then code quality, and fix discovered defects before delivery.
